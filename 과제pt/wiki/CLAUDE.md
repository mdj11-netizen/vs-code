# 회계·세무 Wiki 목업 프로젝트 규칙

이 폴더의 메인 파일은 `2026-08-04_mockup_회계세무Wiki시스템_원본.html` — 단일 HTML 파일, `DOCS` 객체(`"카테고리/leaf"` 키)에 각 페이지 본문을 넣고 공유 함수로 렌더링하는 구조.

## 0. 가장 중요한 원칙 — 데이터는 항상 verbatim

- **S2 분개유형분류코드명 / S2 정산항목명은 노션 원문을 그대로 쓴다.** 절대 의역·축약·재구성하지 않는다.
  - 실수했던 예: "웹툰MG · 기간상각"으로 줄여 썼다가, 실제 원문은 "선급비용 선지급-웹툰MG (기간상각)"이라 다시 전부 고친 적 있음. 띄어쓰기·괄호·구분자까지 원문 그대로.
- 존재 확인이 안 된 항목·분류코드는 지어내지 않는다. 애매하면 만들지 말고 먼저 물어본다.
- 노션/ERP 원문이 주어지면 그 즉시 파일 전체에서 같은 항목이 다른 페이지(예: 유통 > 원가)에도 파라프레이즈된 채로 중복돼 있는지 검색해서 같이 고친다(같은 실수가 여러 곳에 복사돼 있는 경우가 많았음).

## 1. 색상 의미 체계 (사이트 전체 통일 — 새 UI 만들 때 그대로 재사용)

| 역할 | 색 토큰 | 용도 |
|---|---|---|
| 내부 처리 / 정상 케이스 / 항상 보장되는 공통 부분 | `--teal` / `--teal-weak` / `--teal-deep` | `moneyDiagram`의 `company` role, RS≤MG류 "정상" 카드, 비율 막대의 고정분 |
| 외부로 나가는 돈 / 예외 케이스 / 조건부 추가금 | `--coral` / `--coral-weak` / `--coral-deep` | `moneyDiagram`의 `external` role, RS>MG류 "예외" 카드, 비율 막대의 초과분 |
| 브랜드 강조 / 링크 / "예시" 배지 | `--blue` / `--blue-weak` / `--blue-deep` | 사이드바 선택 표시, 챕터 chip, 스크린샷 라벨 배지 — **케이스 구분용 의미색으로는 쓰지 않음** |
| 유저 액션 | gray | `moneyDiagram`의 `user` role |

- 새로 비교 UI(좌우 카드, 비율 막대, 배지 등)를 만들 때는 위 체계를 그대로 가져다 쓴다. 임의로 새 색(커스텀 파스텔 블루/오렌지 등)을 만들지 않는다.
- 한 번 RS≤MG/RS>MG 카드에 blue를 썼다가 teal로 되돌린 적 있음 — blue는 이미 브랜드 전용색이라 "정상/예외" 같은 의미색과 겹치면 통일성이 깨진다.
- 새 색이 필요한 게 명확해 보여도 먼저 기존 teal/coral/blue로 표현이 되는지 생각해보고, 정말 안 되면 그때 제안한다.

## 2. 아이콘 원칙

- 새로 만드는 UI 요소(섹션 라벨, 배지, 토글 아이콘)는 이모지 대신 **stroke 기반 SVG 라인 아이콘**을 쓴다. `sectionLabel()`, `exShotLabel()`, `S2 정산항목` 토글의 아이콘 참고.
- 기존에 남아있는 이모지(콜아웃 `⚠️`/`💡` 등)는 굳이 다 바꾸러 다니지 않아도 되지만, 새로 추가하는 요소에는 이모지를 쓰지 않는다.

## 3. 재사용 컴포넌트 (스크립트 상단 function 선언부 — `DOCS`가 이 함수들을 즉시 호출하므로 여기 있는 함수는 반드시 `function` 선언으로 hoist되어야 함)

| 함수 | 역할 |
|---|---|
| `moneyDiagram(steps)` | "돈의 흐름" 박스+화살표 다이어그램. `role: 'user'\|'company'\|'external'`만 넘기면 색은 함수가 자동 매핑 — 호출부에서 색을 직접 지정하지 않는다 |
| `exampleBlock(items, currentIdx)` | S2 정산항목 대표 예시(스크린샷/placeholder) + 전체 목록. 목록 표는 항상 2열(분류코드명·항목명) 고정, 연속 동일 분류코드는 rowspan 병합, 그리드·접두어 압축 없음, 클릭 인터랙션 없음 |
| `shot(src, maxWidth, label)` | ERP 스크린샷 프레임(흰 배경 카드, 이미지 자체엔 별도 테두리 없음). `label`을 주면 프레임 안쪽 상단 왼쪽에 배지로 얹는다 |
| `exShotLabel(item)` | "아이콘 + 예시 · S2 {분류코드명} · {항목명}" 알약형 배지. 스크린샷이 실제로 있는 모든 곳에 이걸로 통일 |
| `sectionLabel(text)` | 이모지 대신 SVG 아이콘 + semibold 텍스트 + 하단 구분선 — "돈의 흐름" 같은 섹션 소제목에 사용 |
| `toggleS2(btn)` | S2 정산항목 표, 순액법·총액법 비교 등 접이식 토글의 공통 열기/닫기 로직 |

- 새 화면을 만들 때는 이 함수들부터 재사용한다. 화면마다 새로 마크업을 짜지 않는다.
- 정말 새로운 시각 패턴이 필요할 때만 새 CSS 클래스를 추가하고, 기존 전역 스타일(`.card`, 폰트, 사이드바, 헤더 등)은 건드리지 않는다.
- 공유 함수를 고치면 그 함수를 쓰는 모든 페이지에 자동 반영된다는 걸 항상 인지한다 — 한 페이지만 고치라는 요청이라도, 실제로는 공유 컴포넌트라 다른 페이지도 같이 바뀔 수 있다는 걸 미리 알려준다.
- 최상위 `const`/`let` 색상표 등은 함수 몸통 안에 두고 스크립트 최상위에는 두지 않는다 (`DOCS` 객체가 스크립트 위쪽에서 이 함수들을 즉시 호출해서, 최상위 선언은 그 줄 전까지 TDZ라 에러가 남).

## 4. 스크린샷 워크플로우

1. 원본 캡처(흰 여백 있는 그대로)를 `사진/`에 넣는다.
2. `scripts/crop-erp-images.ps1` 실행 → 연한 회색(RGB 204, 허용치 ±20) 테두리를 감지해 바깥 여백만 잘라 `../accounting-wiki/assets/erp/`에 같은 파일명으로 저장. 이미 저장된 파일은 건너뛴다.
3. 여러 장을 한 번에 올릴 때는 실수로 같은 파일이 두 이름으로 중복되거나 다른 예시와 잘못 짝지어질 수 있으니, 진행 전에 이미지를 직접 눈으로 확인(필요하면 md5도)하고 어떤 화면인지 파악한 뒤 연결한다.
4. 이미지는 절대 원본 해상도보다 크게 표시하지 않는다 — `max-width:100%;height:auto` + 부모 `display:inline-block` 패턴 유지.
5. Node.js/Python은 이 컴퓨터에 설치되어 있지 않다. 이미지 크롭 등에 그게 필요한 작업이면 먼저 설치 여부를 물어보고, 대개는 PowerShell + .NET(`System.Drawing`)으로 대체 가능하니 그쪽을 먼저 시도한다.

## 5. 카드/여백/레이아웃 규칙

- 기존 `.card`(흰 배경, `--radius:16px`, `--shadow`) 스타일은 그대로 두고, 새 컴포넌트는 그 안에 넣는다.
- 서로 관련된 섹션(예: 비교 카드 + 그 아래 스크린샷)은 별도 카드로 쪼개지 말고, `border-top:1px solid var(--gray-2)` 구분선만 넣어 하나의 흰 배경 카드로 잇는다. "중간/하단 흰 배경을 연결해달라"는 요청이 이 패턴이다.
- 새 배지·라벨류는 아래쪽에 12px 내외 여백을 두고, 접이식 토글류는 그 위 요소와 최소 10px는 띄운다 — 요소들이 서로 붙어 보이지 않게 한다.
- 좌우 비교 카드(예: RS≤MG/RS>MG)는 흰 배경 + 왼쪽 4px 색상 바(위 색 체계의 teal/coral) 콜아웃 스타일을 기본으로 쓴다. 카드 전체를 색으로 채우지 않는다.
- 값을 비교하는 막대(비율 막대 등)는 `%` 기반으로 늘리지 않고, 실제 금액 비례의 **고정 px 폭**으로 그린 뒤 `width:fit-content; margin:0 auto`로 가운데 정렬한다.

## 6. 진행 방식

- 변경 후에는 항상 headless Chrome(스크래치 폴더에 미러링 → `--dump-dom`/`--screenshot`)로 실제 렌더링 결과와 콘솔 에러(초기 `window.addEventListener('error', ...)`로 `document.title`에 즉시 기록하는 방식)를 확인한 뒤 완료 보고한다.
- 사용자가 참고 이미지를 붙이면, 그 이미지의 "느낌"(레이아웃·간격·구조·비율)만 가져오고 색은 위 색 체계에 맞게 판단해서 고른다 — 이미지 속 색을 그대로 베끼지 않는다(사용자가 "색은 네가 알아서" 라고 자주 말함).
- 구조적으로 크게 갈리는 선택(예: 스크린샷 이미지를 유지할지 실제 데이터로 HTML 표를 새로 그릴지)이 있으면, 진행하기 전에 반드시 사용자에게 확인한다.
